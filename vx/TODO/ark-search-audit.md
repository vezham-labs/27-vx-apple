# Ark feature audit against Search

Reviewed Search at [`6f2b186bfa862d282ee9f424be1dfd5eb8ddc316`](https://github.com/driceroland/Search/tree/6f2b186bfa862d282ee9f424be1dfd5eb8ddc316). Rows follow the [Arc vs. Ark matrix](../../apps-docs/docs/content/docs/ark/comparison.mdx). Search filenames are relative to `Sources/Search` unless noted. The audit records source evidence and distinguishes it from on-device checks.

Current order: complete the Mac audit first. Mobile implementation and device verification resume after the Mac pass.

## Mac automatic video PiP

Search’s `NativePiP.swift` opts into macOS WebKit PiP through the same private `WKPreferences` selector, then requests native presentation from a playing video. Ark adds an opt-in General setting and starts PiP when an eligible video leaves the visible tab group. This increment covers tab switches only; app deactivation and site-specific playback are still open.

On macOS 27.2, an isolated local MP4 fixture confirmed stock `requestPictureInPicture()` returns `NotSupportedError`, while Ark’s native PiP path opens. It verified PiP on tab switch, return to inline playback, muted-video exclusion, site-initiated PiP ownership, and source-tab cleanup before WebView unload. The production Mac Nx build passed. This is functional and lifecycle verification only; no performance claim was measured. The WebKit preference is private and may change across OS releases. iPhone, iPad, Duo, and real streaming services remain unverified. [Mac settings preview](../../preview/ark/mac/features/automatic-video-pip-settings.png)

## Mac archive measurement

The archive pass now builds a set of expired tab IDs before removing them. A local Swift microbenchmark compared only the removal step, including set construction, and verified identical order and remaining IDs in both versions.

| Synthetic workload       | Previous median | Current median |
| ------------------------ | --------------- | -------------- |
| 1,000 tabs, 500 stale    | 1.458 ms        | 0.196 ms       |
| 10,000 tabs, 5,000 stale | 48.433 ms       | 0.713 ms       |

Each median comes from five optimized runs on the local Mac. This measures the filtering step, not total archive or UI latency.

## Mac recent tabs measurement

The picker gathers the tabs visible in other windows once before filtering its candidates. A synthetic two-window fixture compared this against resolving ownership for every candidate. Both versions returned the same tabs in the same order.

| Candidates | Ownership lookup per tab | One lookup per window |
| ---------- | ------------------------ | --------------------- |
| 1,000      | 6.255 ms                 | 0.095 ms              |
| 10,000     | 699.902 ms               | 1.037 ms              |

Each value is the median of five optimized runs on the local Mac. The measurement covers ownership filtering and excludes sorting, WebKit snapshots, and rendering.

## Mac command bar measurement

A standalone Swift benchmark used the previous and current `CommandBarModel` on the same 403-command catalog. It verified identical displayed rows, default selection, arrow movement, and Return actions across ten queries. Across seven paired runs of 320 query updates each, the median fell from 3,114.3 ms to 779.3 ms and command-provider evaluations fell from 8,512 to 2,240. These timings cover row generation and selection logic and exclude SwiftUI rendering and remote suggestions.
