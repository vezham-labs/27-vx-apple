# Ark feature audit against Search

Reviewed Search at [`6f2b186bfa862d282ee9f424be1dfd5eb8ddc316`](https://github.com/driceroland/Search/tree/6f2b186bfa862d282ee9f424be1dfd5eb8ddc316). Rows follow the [Arc vs. Ark matrix](../../apps-docs/docs/content/docs/ark/comparison.mdx). Search filenames are relative to `Sources/Search` unless noted. The audit records source evidence and distinguishes it from on-device checks.

Current order: complete the Mac audit first. Mobile implementation and device verification resume after the Mac pass.

## Mac automatic video PiP

Search’s `NativePiP.swift` opts into macOS WebKit PiP through the same private `WKPreferences` selector, then requests native presentation from a playing video. Ark adds an opt-in General setting and starts PiP when an eligible video leaves the visible tab group. This increment covers tab switches only; app deactivation and site-specific playback are still open.

On macOS 27.2, an isolated local MP4 fixture confirmed stock `requestPictureInPicture()` returns `NotSupportedError`, while Ark’s native PiP path opens. It verified PiP on tab switch, return to inline playback, muted-video exclusion, site-initiated PiP ownership, and source-tab cleanup before WebView unload. The production Mac Nx build passed. This is functional and lifecycle verification only; no performance claim was measured. The WebKit preference is private and may change across OS releases. iPhone, iPad, Duo, and real streaming services remain unverified. [Mac settings preview](../../preview/ark/mac/features/automatic-video-pip-settings.png)

## Mac Mini Player

Search’s `Sources/Search/Float.swift` at [`6f2b186bfa862d282ee9f424be1dfd5eb8ddc316`](https://github.com/driceroland/Search/commit/6f2b186bfa862d282ee9f424be1dfd5eb8ddc316) supplies the floating WebKit player. Ark adapts it in `apps/ark/Mac/Sources/State/VideoMiniPlayer.swift` with an Ark-owned panel, playback controls, resize/dock/tuck behavior, remembered positioning, ⌘K and View-menu entry, and inline return on source-tab selection. Library cleanup closes the panel before a tab unload or engine swap; automatic PiP skips the tab while this player owns it.

On macOS 27.2, `pnpm nx run ark:build-mac` passed. An isolated local fixture ran through Ark’s actual ⌘K command dispatch: the 1280×720 video advanced while the panel was open, WebKit reported a visible decoded frame, and selecting the source tab restored inline playback. The preview uses WebKit’s page snapshot plus Ark’s captured panel controls because the native capture omits the WebKit remote video surface. The fixture is Ark-branded, local, and temporary; this path does not use screen-recording permission. The native Pause and Play buttons changed the video’s paused state and exposed the next action through their accessibility label. A 36-second MP4 fixture verified that the native seek buttons moved from 6.474 to 21.474 seconds and back while paused. Minimize hid the transport controls and reduced the panel to 220 points. Restore returned the panel to its original frame. With the General setting enabled, a horizontal wheel event docked the panel at the right edge with 10 points visible. The reverse event restored its original position. Native corner drag events grew the panel by 60 points with its top-left corner fixed. Height stayed within 0.32 points of the aspect-ratio target. Dragging inward stopped at the 260-point minimum. Physical trackpad gestures and multiple displays still need verification. No Ark GPU benchmark has been run for ordinary video. iPhone, iPad, and Duo remain open.

### Mac profile management

Search's `Profiles.swift` exposes profile creation, renaming, and deletion. Ark's Mac Settings → Spaces now supports the same management for per-Space website profiles. Renaming retains the profile UUID. Deletion asks for confirmation, returns assigned regular Spaces to Default, waits for their WebViews to unload, clears the named store's data and releases its cached configuration, then removes the per-profile history folder, favorites, archive records, and recently-closed records. A WebKitEngine regression test verifies that a recreated store has no prior cookie; WebKit can keep the empty store registered while its network process still uses it. BrowserKit's 59 tests passed, including profile-name validation and history-directory removal, and `pnpm nx run ark:build-mac --skip-nx-cache --output-style=static` passed. Runtime deletion through Mac Settings remains unverified. Mobile rename/delete and Duo checks remain open. The current debug bundle ID is `app.vezham.ark.dev`; Launch Services returns `kLSNoExecutableErr` when opening the built bundle, and screen recording access is unconfirmed, so a new UI preview is pending. Search reference SHA: `6f2b186bfa862d282ee9f424be1dfd5eb8ddc316`.

### Content-blocking updates finishing out of order

Ark's `WebKitEngine.applyBlocking` now assigns compiled rules only after checking that the requested settings are still current. Previously, enabling blocking and then disabling it while compilation was pending could leave stale rules cached for subsequently registered pages even though existing pages had their rules removed. A temporary Swift harness extracted the actual method and used a suspended compiler stub: before the fix the cache contained old rules while installed rules were empty; afterward both remained empty. This verifies the async state transition, not live WebKit network blocking. `pnpm nx run ark:build-mac` passed. No persistent test files or screen-recording access were needed. Search reference remains `6f2b186bfa862d282ee9f424be1dfd5eb8ddc316`; this is an Ark engine correctness fix.

### Mac extensions in named profiles

Search `Profiles.swift` and `Extensions.swift` at `6f2b186bfa862d282ee9f424be1dfd5eb8ddc316` share one extension controller across profiles. Ark now attaches its existing shared controller to named-profile configurations, preserving each website data store. Installed extensions and their own settings remain shared, not isolated per profile.

The Mac fixture loaded a local Manifest V3 extension through Ark's actual extension loader. Its content script changed the named-profile page, while Default cookies and local storage were absent there; writing named-profile values left Default unchanged. The fixture also exposed an options-page failure: normal tab creation supplied the extension URL after creating its web view. Extension URLs now reach page creation first so WebKit selects the extension's own configuration. The same options page changed from a blank page with `NSURLErrorDomain -1008` to loaded content with no navigation error.

The Mac build passed. The temporary runtime hook was removed from `SnapshotTour.swift`. The [preview](../../preview/ark/mac/features/named-profile-extension.png) is a real WebKit page snapshot of the local content-script fixture, not a screenshot of a third-party extension. Store-extension compatibility, private-profile extension access, and cross-profile extension messaging were not validated by this fixture. The Profiles row remains Partial for the outstanding scope.

### Mac extension unload lifecycle

Search `Extensions.swift` at `6f2b186bfa862d282ee9f424be1dfd5eb8ddc316` invalidates pending load tickets and retires extension resources on unload. Ark now invalidates its pending load generation, cancels keep-alive timers, stops and releases hidden keep-alive web views, and clears ping timestamps before unloading contexts.

A temporary Mac runtime fixture loaded a local MV3 background extension twice and inspected actual timers and weak web-view references after each unload. Before the fix, each unload retained one valid timer and one hidden view. After the fix, both cycles retained zero timers, the previous timers were invalid, and the views were released. A controlled suspension immediately after the async extension constructor tested unload during loading: the old code ended with one extension, timer, and view; the fixed code ended with zero of each. No fixture errors were reported. The artificial suspension makes the race repeatable; it is not an extension startup benchmark.

Temporary instrumentation was removed. The final Mac build passed. These checks establish resource teardown and cancellation behavior, not a quantified RAM, CPU, or battery improvement. Extension compatibility ratings remain unchanged.
